# 工程师开发要求

> 本文档定义了契约式开发模式下的工程实践规范，包括契约管理、测试要求和 Review 流程。

## 背景

本文档定义团队工程师在日常开发中必须遵循的规范和流程，确保代码质量和协作效率。

## 契约式开发

### 1. 契约优先

- 所有代码开发基于标准契约（Contract）进行
- 契约文件夹位于 `contract/` 目录
- 通过契约生成代码，而非直接编写实现

### 2. 契约保护

**禁止修改 `contract/` 文件夹中的任何内容**

- 契约是系统的基础规范，不可擅自更改
- 如需修改契约，需通过正式的变更流程申请

## 开发流程

### 3. 单元测试要求

- 开发必须编写单元测试
- 测试覆盖所有新增和修改的功能
- **测试通过前，流程中断，需请求 Review**

### 4. Review 流程

```
编写代码 → 编写单元测试 → 请求 Review → Review 通过 → 后续操作
```

- Review 通过后，方可进行后续操作
- Review 应关注代码质量、规范符合度、测试完整性

### 5. 代码完成检查

编写代码完成后，必须执行以下检查：

1. **Lint 检查** - 确保代码符合规范
2. **单元测试** - 确保所有测试通过

### 6. Contract Schema 验证

在执行单元测试前，**必须执行一次 Contract Schema Generator**：

```
Contract Schema Generator → 单元测试
```

- 确保没有使用改动后的 Contract Schema
- 验证契约与实现的一致性
